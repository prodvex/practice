# GamingClub.Android — вариант 18

Android-клиент на Kotlin для Android Studio. Исходники находятся в ветке `feature/android-client` (draft PR №1).

## Реализованный прототип

- Загрузка мест и тарифов через настоящий `GamingClub.API`.
- Выбор места, тарифного плана и времени UTC.
- Тестовое создание бронирования через `POST /api/dev/bookings`.
- Запуск сессии, запрос таймера и продление на 30 минут через API.

**Важное ограничение:** авторизация, регистрация, автоматический таймер, сохранение состояния при пересоздании Activity и полноценный интерактивный план зала пока отсутствуют. Это не финальные шесть экранов, а один скроллируемый прототип.

## Проверка в Android Studio

1. Установите JDK 17, Android Studio, Android SDK Platform 35.
2. Откройте папку `mobile/GamingClub.Android` как Gradle-проект. Если Android Studio предложит загрузить Gradle, согласитесь. Gradle wrapper ещё не добавлен.
3. Выполните подготовку SQL Server и API по `docs/local-setup.md` в ветке `main`.
4. На компьютере запустите API в Development на `http://localhost:5080`.
5. Используйте Android Emulator: адрес `10.0.2.2` в `BuildConfig.API_BASE_URL` указывает на компьютер с API.
6. Соберите и запустите debug-версию вручную через Android Studio.
7. Введите реальный `UserId` тестового пользователя из SQL. Выберите активное место и тариф.
8. Выберите два будущих момента UTC с точностью до минуты и создайте бронь. Повтор с пересечением должен показать ошибку HTTP 409.
9. Для запуска сессии её бронь должна уже начаться: создайте вторую тестовую бронь, начало которой находится в прошлом, а конец — в будущем; после этого проверьте кнопки запуска, чтения таймера и продления.
10. Для теста конфликта заранее забронируйте тот же ПК на время, которое захватит продление; ожидается HTTP 409.

**Безопасность:** запросы записи работают только с серверным Development API без авторизации. Не публикуйте такой сервер в сети. HTTP разрешён в Android только в Debug; release не содержит рабочего публичного адреса API и демонстрационные операции отключены.

## Известные ограничения

- Текущее приложение показывает список мест, а не геометрическую схему с координатами.
- Время задаётся строкой ISO 8601 в UTC.
- Таймер обновляется по кнопке, не автоматически.
- Отсутствуют APK и подтверждённые результаты сборки/тестов.
- Для реального устройства нужен безопасный HTTPS endpoint, а не `10.0.2.2`.
