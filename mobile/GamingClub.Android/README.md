# GamingClub.Android — вариант 18

**Статус:** Android Studio/Kotlin, исходники в ветке `feature/android-client`, draft PR №1. Сборка, APK, эмулятор и тесты **не запускались**.

[Шесть редактируемых экранов Figma](https://www.figma.com/design/Gh6UqShvMOH9IWPghqE95P) и HTML-прототип в `docs/design/prototype.html` — макеты, не скриншоты работающего приложения.

## Шесть разделов

1. **Вход** — вход или регистрация роли `VISITOR` с JWT.
2. **Зал** — геометрический план компьютеров по координатам SQL и выбор места.
3. **Бронирование** — тариф, начало/конец UTC, отправка на защищённый API.
4. **Мои брони** — список владельца, открытие и отмена будущих активных броней с подтверждением.
5. **Сессия** — запуск, серверный таймер `HH:mm:ss` с опросом каждые 5 секунд, продление на 30 минут.
6. **Профиль** — имя, роль, выход и очистка данных предыдущего аккаунта.

Разделы переключаются через закреплённую внизу панель с выделением выбранного раздела. Оформление основано на тёмной палитре Figma (`ClubUi.kt`), но сейчас это **одна Activity**, а не шесть независимых Fragment.

## Локальная настройка

1. В SSMS создать локальную БД через `database/schema.sql`, затем применить `database/seed.sql`. Если база создана по старой схеме — отдельно применить `database/migrations/001_void_pending_payments.sql`.
2. На компьютере настроить `ConnectionStrings__GamingClub` и `GAMINGCLUB_JWT_SECRET` по `docs/auth-verification.md`. Использовать только синтетические пароли.
3. Локально запустить API на `http://localhost:5080`, Development, без публичного сетевого доступа.
4. В Android Studio открыть `mobile/GamingClub.Android`, выбрать JDK 17, SDK 35 и Android-эмулятор.
5. Использовать Debug: `10.0.2.2:5080` — компьютер с API с точки зрения эмулятора. Debug-манифест и `debug_network_security_config.xml` разрешают HTTP **только к 10.0.2.2**. Release не имеет такого исключения и рабочего URL.

После успешной регистрации выберите активный ПК, будущий UTC-интервал по целым минутам и тариф. При HTTP 409 скорректируйте время. Запуск сессии разрешён только внутри времени бронирования. После выхода токен и личные списки удаляются из памяти Activity.

## Открытые ограничения

- Android-вёрстка, работоспособность реального API и APK пока не проверены. Дизайн может требовать коррекции после просмотра эмулятора.
- Авторизация живёт только в оперативной памяти; после перезапуска Activity потребуется новый вход.
- Вычисления стоимости, наличия места на интервал и статуса оплаты подтверждает **сервер**, а не цвет плана.
- Нет платёжного шлюза, production HTTPS endpoint, окончательной поддержки часового пояса и тестов UI.
- Публиковать Development API в Интернет нельзя. Release-сборку с заглушкой `example.invalid` нельзя считать готовой к эксплуатации.
