# Контракт Android ↔ GamingClub.API (вариант 18)

**Статус:** API, Android APK и SQL Server реально проверены. **85 .NET-тестов и 31 JVM-тест PASS**; Android 15 Emulator подтвердил установку APK и открытие MainActivity. Полный Android→SQL UI-сценарий пока не автоматизирован.

Android-исходники объединены с `main` через PR #1; SQL/HTTP-тесты объединены через PR #2.

## Экраны и маршруты

| Раздел Android | HTTP | Что проверяет сервер |
|---|---|---|
| Вход | `POST /api/auth/login` | Логин и пароль, выдача JWT |
| Регистрация | `POST /api/auth/register` | Создаёт только `VISITOR` |
| Зал | `GET /api/seats` | Возвращает компьютер, координаты `x/y`, `isActive` |
| Тарифы | `GET /api/tariffs` | Только действующие тарифы |
| Бронирование | `POST /api/bookings` | JWT, пересечения и стоимость; userId из токена |
| Мои брони | `GET /api/bookings/mine` | Только брони владельца |
| Отмена | `POST /api/bookings/{id}/cancel` | Владелец, будущая активная бронь |
| Старт сеанса | `POST /api/sessions/{id}/start` | Владелец, время старта, статус |
| Таймер | `GET /api/sessions/{id}` | Оставшееся время по серверному UTC |
| Продление | `POST /api/sessions/{id}/extend` | Владелец, конфликт, доплата |

**Важно:** запрос создания брони **не содержит** `userId`. Даже если злоумышленник пошлёт его вручную, маршруты защищённого API используют идентификатор из JWT.

## Правила обработки

- Пользователь выбирает место на геометрической схеме зала. Цвет показывает статус компьютера `IsActive`, **не** доступность на выбранные даты. Конфликт проверяется только сервером.
- Начало/конец вводятся в формате ISO-8601 с UTC, например `2030-01-05T12:00:00Z`; клиент отклоняет нецелые минуты, конец раньше начала и интервал более 7 суток.
- После входа JWT хранится **только в памяти**, не в `SharedPreferences` и не в исходниках. После закрытия приложения необходимо войти снова.
- Устаревшие результаты сетевых задач не применяются после выхода. При смене аккаунта старые задачи сбрасываются; 401 для действующей сессии возвращает на вход.
- После старта игровой сессии Android запрашивает серверный таймер каждые 5 секунд, пока Activity активна, отображая часы/минуты/секунды.
- Отмена будущей брони требует подтверждения. `VOID` — отменённое неоплаченное начисление, **не** возврат денег.

## Сетевые ограничения

Debug использует `http://10.0.2.2:5080`, доступный из Android-эмулятора при работающем на компьютере API. Файлы:

- `mobile/GamingClub.Android/app/src/debug/AndroidManifest.xml`
- `mobile/GamingClub.Android/app/src/debug/res/xml/debug_network_security_config.xml`

Разрешено незашифрованное соединение **только** с `10.0.2.2` в Debug. На Release это исключение не распространяется, а адрес `https://example.invalid` является заглушкой. Перед публичной публикацией потребуются действующий HTTPS API, домен и дальнейшие проверки безопасности.

## Проверки Android без SQL Server

На ветке `feature/android-client` написан **31 JVM unit/contract тест**:

- **12** — `BookingDraftValidatorTest`: даты, интервал, полные минуты и невалидные идентификаторы;
- **4** — `AuthAttemptGuardTest`: последовательность входов и устаревшие ответы;
- **6** — `SessionClockFormatterTest`: формат серверного таймера;
- **9** — `GamingClubApiContractTest`: реальный `HttpURLConnection` против локального MockWebServer, JWT, запросы бронирования/отмены и ответы 401/409.

Будущая команда локальной проверки из папки `mobile/GamingClub.Android`:

```powershell
./gradlew.bat :app:testDebugUnitTest
```

Если Gradle Wrapper не добавлен, используйте команду Gradle из Android Studio или Gradle установленный в системе. Команда приведена для повторения: фактически в CI `gradle :app:testDebugUnitTest` и `assembleDebug` успешно выполнялись, APK устанавливался и запускался на эмуляторе.
