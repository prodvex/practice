# Полный аудит проекта, Android и WPF

Дата ревизии: 19.11.2026.

Проверены исходники `main`, Android-клиент, WPF-клиент, ASP.NET Core API, SQL-схема, тесты, workflow и документация. Статическая проверка `scripts/static_audit.py` прошла 51/51. Полную компиляцию в текущем Linux-окружении запустить нельзя, потому что здесь нет .NET SDK, Windows WPF toolchain и Gradle.

## Android

### Критические ограничения

1. Release-сборка не является рабочей. В `MainActivity` при `BuildConfig.DEBUG == false` показывается сообщение о тестовом клиенте, а `release` использует `https://example.invalid`.
2. Полный сценарий Android → API → SQL Server не подтверждён. Подтверждены JVM-тесты и запуск Activity на эмуляторе.
3. В репозитории нет Gradle Wrapper. Команда `gradlew.bat` из документации не может быть выполнена из скачанного архива без установленного Gradle или Android Studio.

### Незавершённые функции

- нет production HTTPS URL и release-конфигурации;
- токен хранится только в памяти, после перезапуска требуется новый вход;
- нет UI-тестов и проверки на физическом телефоне;
- план зала показывает `IsActive`, но не занятость на выбранный интервал, поэтому окончательное решение принимает сервер;
- нет отдельного действия завершения игровой сессии;
- Figma Present не проверен вручную.

### Ошибок контракта не обнаружено

Маршруты Android совпадают с API. `userId` не передаётся при защищённом бронировании, JWT добавляется к защищённым запросам, ответы 401/409 обрабатываются, устаревшие ответы после выхода отбрасываются.

## WPF / ПК

### Критические ограничения

1. WPF-клиент рассчитан только на Windows и не проверяется локально в текущем окружении. Последняя подтверждённая сборка относится к GitHub Actions.
2. В клиенте нет production HTTPS-настройки по умолчанию. Адрес берётся из `GAMINGCLUB_API_URL`, иначе используется `http://localhost:5080`.
3. Реальная карта зала не реализована. Сейчас отображается список карточек мест без координатной схемы и без статуса занятости по интервалу.

### Незавершённые функции

- нет кнопки завершения сессии;
- запуск сессии из WPF отдельно не представлен, есть только продление по ID;
- отчёт ограничен последними 100 бронированиями в административном списке;
- даты отчёта в окне заданы демонстрационными значениями и не подставляются динамически;
- нет UI-тестов WPF и проверки на реальном Windows-компьютере;
- README WPF ранее содержал устаревший статус «проект ещё не создан», его необходимо синхронизировать с исходниками.

### Что работает по исходникам

Есть вход только для ADMIN, загрузка мест, список бронирований, отмена будущей активной брони, создание и отключение тарифов, расчёт загрузки и экспорт CSV.

## API и база данных

- JWT, PBKDF2, роли и rate limit реализованы.
- `/api/dev/*` доступны только в Development и обходят авторизацию. Такой сервер нельзя публиковать.
- Платёжного шлюза и возвратов денег нет. `PENDING` и `VOID` описывают учебные начисления.
- В API нет отдельной операции завершения сессии, поэтому статус брони и `FinishedUtc` не переводятся автоматически пользовательским действием.
- Тарифные окна называются `LocalTime`, но политика часового пояса клуба не задана. Сейчас расчёт использует UTC.
- Бронирование в текущем API может быть создано с началом в прошлом. Это нужно либо явно разрешить для запуска текущей сессии, либо запретить отдельным правилом для будущих броней.

## Документация и процесс

- ТЗ требует реальную организацию и подписи.
- Итоговые отчёты, дневник, аттестационный лист, характеристика и презентация отсутствуют.
- Тест-кейсы составлены, но таблица фактических результатов и скриншотов не заполнена.
- В репозитории 242 коммита, тег `v1.0.0` существует, но все коммиты относятся к одному календарному дню.
- `data/` отсутствует, хотя каталог заявлен в структуре проекта.
- Журнал использования ИИ ещё не заполнен фактическими запросами.
