# Проверка отчёта о загрузке зала (ручной тест)

**Статус:** инструкция для будущего локального прогона, не доказательство прохождения теста.

## Определение метрики

Загрузка (%) = занятые компьютер-минуты / доступные компьютер-минуты × 100.

В числитель входят интервалы бронирований со статусом `ACTIVE` или `COMPLETED`, ограниченные выбранным интервалом. В знаменатель входят активные игровые места из `dbo.Seats`. Пересекающиеся интервалы одного места объединяются, чтобы результат не превышал 100%. Отменённые брони исключены.

Ограничение текущей модели: количество активных мест берётся **на момент запроса**, а не из исторического состояния. Поэтому отчёт за прошлые месяцы не учитывает изменение состава зала; для исторически точных отчётов потребуется отдельная история доступности мест.

## Как проверить в Swagger (только Development)

1. Запустите SQL Server и API по `docs/local-setup.md`.
2. Откройте `http://localhost:5080/swagger`.
3. Вызовите `GET /api/dev/reports/occupancy` с параметрами:
   - `from=2026-11-20T14:00:00Z`
   - `to=2026-11-20T15:00:00Z`
4. Для пустой таблицы бронирований ожидается `seatCount: 12`, `occupancyPercent: 0`.
5. Создайте бронирование одного места на весь выбранный час через `POST /api/dev/bookings` (ID берите из SQL).
6. Повторите отчёт: для 12 мест и 1 часа занятого времени ожидается `occupancyPercent: 8.33`.
7. Вызовите `GET /api/dev/reports/occupancy.csv` с теми же параметрами и откройте скачанный CSV в Excel. В CSV должны быть заголовок, значения и seed `241810`.

## Негативные случаи

- `from >= to` → HTTP 400.
- Продолжительность >31 дня → HTTP 400.
- `CANCELLED` не входит в статистику.
- Два пересекающихся бронирования одного места не должны удвоить время.

**Важно:** пример выше работает при исходных 12 активных местах и отсутствии иных пересекающихся броней. Эти запросы не защищены авторизацией и предназначены только для локальной отладки, не для публикации.
