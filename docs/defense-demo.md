## До защиты

Подготовить Windows с Visual Studio 2022 и SQL Server Express/Developer, Android Studio с эмулятором и тестовую базу. Выполнить SQL-миграцию `database/migrations/001_void_pending_payments.sql` на созданной ранее базе. Подготовить строго локальный API, тестовые аккаунты, JWT и отчёт о прогоне тестов. Сборку/скриншоты необходимо сделать фактически, не воспроизводить фиктивные результаты.

## Вопросы преподавателя

**Почему нельзя забронировать один ПК дважды?** Сервер проверяет пересечение полуоткрытых интервалов `[start, end)` под блокировками SQL и сериализуемой транзакцией.

**Как считается загрузка зала?** Числитель — занятые компьютер-минуты, знаменатель — вместимость зала за интервал; пересечения одного места объединяются.

**Зачем две роли?** Посетитель бронирует и управляет собственными сессиями; администратор видит общую статистику, тарифы и все бронирования.

**Что делает отмена?** Только будущая активная бронь без начатой сессии и оплаченных начислений может быть отменена. Неоплаченные счета получают `VOID`; реальных возвратов нет.

**Что ещё не завершено?** Сборка/интеграционный прогон, кликабельные связи в Figma, безопасное развёртывание, финальный отчёт и релизный APK.
