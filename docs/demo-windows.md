# Запуск GamingClub на Windows

1. Распакуйте весь архив на локальный диск в папку с правом записи.
2. Дважды щёлкните `Start-GamingClub.cmd`. Для проверки без Android можно запустить `Start-GamingClub.cmd -NoAndroid` из CMD.
3. При запросе на установку LocalDB или Android SDK прочтите условия и подтвердите установку. Для системных компонентов Windows запросит права администратора. При отключённой платформе гипервизора подтвердите её включение. Если потребуется перезагрузка, после неё снова откройте скрипт.
4. Войдите в WPF как `club_admin_18` и в Android как `club_visitor_18`. Пароли для текущего запуска выводятся в консоли вместе со ссылкой на Swagger.
5. Для остановки введите `STOP`. Брони сохраняются при следующем запуске из этой папки под тем же пользователем Windows.

## Требования

- 64-разрядная Windows 10/11 на Intel/AMD. Для Android нужны включённые VT-x/EPT или AMD-V/SVM и работающий гипервизор Windows. Если виртуализация отключена в BIOS/UEFI, включите её средствами ПК.
- Для первой установки компонентов нужны интернет и свободное место для Android SDK и образа. Рекомендуется 12 ГБ свободного места на диске и 16 ГБ оперативной памяти.
- API и WPF опубликованы с .NET 8 x64. ZIP включает APK и переносимый Python. Android Studio, Gradle, SSMS и Visual Studio для демонстрации не нужны.

## Демонстрация

1. В Android откройте «Зал», выберите ПК и забронируйте свободный интервал. Для запуска сессии текущий момент должен попадать в интервал. Время задаётся с точностью до целой минуты.
2. Найдите бронь в разделе «Мои» и откройте «Сессия». Проверьте запуск, таймер, продление и завершение.
3. В WPF откройте «Бронирования» и обновите список. В отчётах выберите период UTC и вид «Загрузка зала» или «Выручка». Нажмите «Экспорт CSV» для сохранения.

В выручке `paid_rub` суммирует записи `PAID`, а `pending_rub` — начисления `PENDING`. Строки `VOID` и `REFUNDED` исключаются. Период отбирается по `PaidUtc`. Учебные бронь и продление создают начисления без приёма оплаты.

## Диагностика и пересборка

- `Start-GamingClub.cmd -ServerOnly` запускает SQL и API.
- `Start-GamingClub.cmd -AndroidSdk "C:\Android\Sdk"` использует указанный SDK с подходящим образом или готовым AVD.
- Журналы находятся в `.local`. Для SQL смотрите `localdb.log` и `database.err.log`, для API — `server.out.log`, для Android — `emulator.out.log` и `adb.err.log`.
- Для каждой папки запуска создаётся отдельный экземпляр LocalDB. Файлы новой базы хранятся в ее каталоге `.local/sql`. Новая распаковка начинает с чистых демонстрационных данных.
- Исходники собираются командой `scripts/Build-GamingClub.ps1 -PublishDemo -BuildAndroid`. Для пересборки нужны .NET SDK, JDK, Gradle и Android SDK. Лаунчер использует официальный комплект Python x64 Embeddable из `runtime/python`.

Запуск Android и управление процессами адаптированы из учебного примера МФЦ, предоставленного вместе с заданием.

## Импорт коммитов

В рабочем клоне GamingClub импортируйте отдельную ветку из переданного файла
`GamingClub-commits.bundle`. Выполняйте команды из каталога клона и подставьте
фактический путь к bundle.

```powershell
git fetch "C:\путь\GamingClub-commits.bundle" refs/heads/gamingclub/stand:refs/heads/gamingclub/stand
git log --oneline main..gamingclub/stand
```

Базовый коммит пакета — `1ceae40`. Для переноса ветки в `main` можно выполнить
`git switch main`, затем `git merge --ff-only gamingclub/stand`. Если ваша
ветка `main` уже разошлась с переданной, Git остановит быстрое слияние.
