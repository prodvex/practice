# Ручная проверка запуска и таймера сессии

**Статус:** сценарий не запускался. Предназначен для выполнения на Windows после сборки API.

## Подготовка

1. Установите SQL Server и выполните `database/schema.sql`, затем `database/seed.sql`.
2. Запустите API в `Development` на `http://localhost:5080`.
3. Создайте бронь через `POST /api/dev/bookings` на **текущий интервал UTC**, включающий текущее время, например от 5 минут назад до 60 минут вперёд (с округлением до целой минуты). ID пользователя и места получите в SQL.
4. Запишите `bookingId` из ответа.

## Проверка

1. `GET /api/dev/sessions/{bookingId}` до запуска должен вернуть HTTP 404.
2. `POST /api/dev/sessions/{bookingId}/start` должен вернуть HTTP 200 при действующей брони.
3. Повторите запуск: ожидается HTTP 400 (сессия существует).
4. `GET /api/dev/sessions/{bookingId}` должен вернуть `sessionId`, `startedUtc`, `endsUtc`, `remainingSeconds`.
5. Подождите несколько секунд и повторите запрос: `remainingSeconds` должен уменьшиться.
6. Вызовите `POST /api/dev/sessions/{bookingId}/finish` в локальном Development API. Этот маршрут предназначен для ручной проверки и не требует JWT. Ожидается HTTP 200, `FinishedUtc` заполняется, а статус брони становится `COMPLETED`.
7. Попробуйте запустить сессию для брони, которая ещё не началась: ожидается HTTP 400.
8. Попробуйте запустить сессию для уже завершившейся по времени брони: ожидается HTTP 400.

## Ограничения

- Ручное завершение сессии реализовано в Development и защищённом маршруте. Платёжный шлюз и автоматическое завершение по истечении времени пока не реализованы.
- Операции создания/старта сессии доступны исключительно в режиме `Development`.
- Таймер рассчитывается сервером и не зависит от часов телефона.
- Реальные результаты тестирования, скриншоты и найденные ошибки нужно сохранить после локального запуска.
