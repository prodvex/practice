# Техническое задание (черновик, вариант 18)

**Тема:** Бронирование игровых мест и учёт сессий компьютерного клуба.  
**База практики:** требуется указать реальную организацию и согласовать с руководителем.  
**Статус:** черновик, НЕ согласовано.

## Роли
- **Посетитель:** вход, схема зала, поиск свободных мест, создание брони, просмотр времени сессии, запрос продления.
- **Администратор:** список мест, бронирования, управление сессиями, тарифами и просмотр загрузки/отчётов.

## Сценарии
1. Посетитель выбирает место и интервал; сервер атомарно проверяет пересечения и создаёт бронь.
2. Администратор запускает сессию по брони; сервер хранит UTC-время начала и конца.
3. При продлении сервер заново проверяет отсутствие конфликтов и рассчитывает доплату.
4. Модуль рассчитывает стоимость с учётом пакетов часов, ночного тарифа и Happy Hours; правила приоритетов фиксируются до реализации.
5. Администратор получает показатель загрузки зала за период и выгружает CSV.

## Функциональные ограничения
- Запрет пересечения активных броней одного компьютера (интервал вида [start, end)).
- Нулевая/отрицательная продолжительность недопустима.
- Недоступные/отключённые компьютеры нельзя бронировать.
- Пересчёт суммы — только на сервере, а не в Android.
- Логи и набор тестовых данных показывают seed 241810.

## Нефункциональные требования
- REST API + OpenAPI/Swagger.
- SQL Server, нормализованная схема (не менее 5 таблиц).
- Не менее 6 экранов Android, 8 API-эндпоинтов.
- Не менее 15 модульных и 5 интеграционных тестов; покрытие ≥70%.
- Пароли хешируются; секреты не хранятся в Git.

## Приёмка
Демонстрация Android→API→SQL Server, ПК→API→SQL Server, защита от двойной записи, расчёт на граничных данных, экспорт CSV, APK и инструкция запуска.
